## 6. 修复：播放进度条不走动（Django DEBUG 媒体 + duration=Infinity 坑）
**现象**：音频能播，但底部进度条不立即走动（甚至一直停在 0%）。
**根因**：Django `DEBUG` 下 `MEDIA_URL` 用 `django.views.static.serve` 提供文件，对 `<audio>` 的 `Range` 请求返回 **`200`（非 `206`）且不带 `Accept-Ranges`**。浏览器因此对资源判定为「不可 seek」，在整文件缓冲完之前把 `audioPlayer.duration` 报成 **`Infinity`**。`updatePlayerProgress()` 用 `if (audioPlayer.duration)` 做守卫 → `Infinity` 被当作 0 → 宽度永不更新。
**实测佐证**：`curl -H "Range: bytes=0-1023"` 返回 `HTTP/1.1 200 OK` + `Content-Length: 5294724`，**无 `Accept-Ranges`**。
**修复**（`js/app.js`）：新增 `getEffectiveDuration()`，优先用 `audioPlayer.duration`，不可用时回退到 API 已提供的 `currentEpisodeData.audio_duration`（真实集数时长，如 120s）。并在 `updatePlayerProgress`、进度条 `loadedmetadata`、`seekToProgressPosition`、`updatePreviewTime`/`resetPreviewTime` 全部改用它。进度条立即随 `currentTime` 走动，拖拽定位/预览也不再因 duration=Infinity 失效。
**附带**：`index.html` 缓存版本 `?v=20260726f` → `?v=20260726g`（app.css/data.js/api.js/app.js 共 4 处），强制浏览器取新 JS。
**可选增强（未做）**：要让原生 seek 与精确 duration 生效，可在 dev server 让媒体支持 `Range`（`Accept-Ranges`/`206`）；前端回退已彻底解决「进度条不动」问题。

## 14. 【真正根因】body 是独立滚动层 → 所有 window 滚动 API 失效（#12/#13 未生效的原因）
**现象**：#12/#13 修复代码都对但用户实测无效。用 puppeteer-core + 本机 Chrome 真实复现，发现 `document.documentElement.scrollHeight===900`（=视口）永远不滚，`window.scrollY` 恒 0。
**根因**：`css/app.css:27` `html, body { height:100%; overflow-x:hidden }` —— ①`height:100%` 把 `<html>` 钉死在视口高度；②CSS 规范：设 `overflow-x:hidden` 会把 `overflow-y` 计算为 `auto` → **`<body>` 变成独立内部滚动层**。用户看到的"右侧滚动条"其实是 body 的，`window.scrollTo()/scrollY` 全部空转。
**修复**：
- CSS：`height:100%` → `min-height:100%`，且 `overflow-x:hidden` **只留在 `<html>` 上**（若留在 body 上，body 仍是滚动容器，会导致 `position:sticky` 吸顶失效——已实测踩坑并修复）；
- JS：`scrollToTopInstant()` 加兜底，遍历 `scrollingElement/documentElement/body` 全部归零。
**验证**（puppeteer-core 无头 Chrome 三场景 + 回归）：A 滚到底点播客→进详情 scrollY=0 PASS；B 直开 #detail/backend-6 顶部 PASS；C 文档级滚动恢复（scrollY 随滚轮变化）PASS；回归：分类条吸顶 top=64 PASS、播放条 fixed PASS。缓存 `n`→`o`（4 处）；CSS 括号 594/594。

## 16. 【真正根因】点击进度条/±10s 按钮都"从头开始加载" → 媒体不可 seek
**现象**：改完进度条样式后用户测试发现：点击进度条到任意位置、点快退/快进 10s，全部失效，都变成"进度条从头开始加载"（currentTime 被重置到 0）。

**根因**：媒体由 Django DEBUG 的 `static()` 助手（`django.views.static.serve`）托管，它**不返回 `Accept-Ranges`**、对 Range 请求也只回 `200`。浏览器据此把 `<audio>` 判定为**不可 seek**；在文件未缓冲到目标位置时点 seek，浏览器把 `currentTime` **钳制回 0** → 表现就是"从头加载"。（#6 已确认该 WAV 的 GET 无 Accept-Ranges。）

**修复**：
- **后端**：`backend/config/urls.py` 新增 `serve_media()` 替代 `static()` 媒体托管——支持 `Range` 请求，回 `206 Partial Content` + `Content-Range`，且**所有响应都带 `Accept-Ranges: bytes`**（含初始 200 全量响应，这样浏览器一开始就知道可 seek）；做路径穿越防护 + `mimetypes` 推断类型；DEBUG 块不再用 `static()`。Django DEBUG reloader 自动热重载生效（curl 验证：GET 带 `Accept-Ranges: bytes`、Range 请求回 `206`）。
- **前端**：新增统一 `seekToTime(seconds)` 助手，同时覆盖**真实 `<audio>`** 与 **simulatePlayback 兜底模式**（后者原来完全忽略 seek，因为时钟在 `simulatedTime` 而非 `audioPlayer.currentTime`）。把以下 seek 站点全部改走 `seekToTime`：`seekToProgressPosition`（点击进度条）、快退/快进按钮、键盘 ←/→、字幕行跳转 `seekTranscriptLine`。
**验证**（puppeteer-core + 本机 Chrome 真机，登录 admin 后 `playEpisode` 播 backend 播客）：
- 真实音频模式：点击 70% → 00:02/2% 跳到 **01:24/70.2%**；快进 → 01:34/78.9%；快退 → 01:25/70.9%。PASS。
- 模拟播放模式（禁自动播放）：结果一致，PASS。
- 三场景均 PASS；顺带回归：progress 条单线/标签自动隐藏未受影响。
**附带**：缓存 `p`→`q`（4 处）；`node --check` 通过；临时诊断脚本已删。

## 关注功能 bug（#11）：关注页刷新后清空 / 关注后看不到
**现象**：详情页点关注→我的关注页看不到；在关注页刷新后显示"还没有关注任何播客"。
**真机复现**（puppeteer，admin 登录）：刷新后 `localStorage.favorites` 仍有 `["backend-8","backend-10","backend-1"]`，但 follow 网格 **0 子元素**（即使 backend 加载完也空）→ 确认是渲染时序问题。另发现控制台报错 `API Error: SyntaxError: Failed to execute 'json' on 'Response': Unexpected end of JSON input`（DELETE /favorites/ 回 204 无 body 被当 JSON 解析）。

**根因**：
1. 渲染时序：`restorePageFromHash()` 在 `DOMContentLoaded` 时（第~190行）就调 `renderFollowPage()`，此时 `loadBackendPodcasts()` 还没 resolve（异步，第150行发起）。`getVisiblePodcasts()` 在 backend 未加载时只返回本地 mock（id 非 `backend-` 前缀），`favorites.has(p.id)` 恒 false → 空网格；backend 加载完后只重渲染了 home，没重渲染 follow 页，于是永久空。
2. `apiRequest` 无条件 `response.json()`，204 无 body 直接抛错（被 swallow 但污染控制台）。

**修复**：
- `js/api.js`：`apiRequest` 新增 `parseBody()` 助手，对 204 / 空 body 返回 null，错误响应也做安全解析；401 retry 同样用 `parseBody`。消除 JSON 报错。
- `js/app.js` `loadFavoritesFromBackend()`：**改为 MERGE 而非覆盖**（遍历后端收藏 add 进 `favorites`），避免后端偶发为空时把 localStorage 里的收藏清空。
